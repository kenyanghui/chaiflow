# 运维手册：内容章名的人性化命名（拆生活指南 31 章）

> 适用：chailive（www.aibay.asia/chailive/）等任何「分类词当标题」的内容站。目标：把图书馆式分类名改成普通人想点进去的话。

## 一、问题：分类词是给编辑看的，不是给读者看的

首版 31 章沿用了归类时的分类词：沟通表达 / 自我认知 / 思维模型 / 心理疗愈……归类任务里它们是好键值（可判定、互斥、完备），但当章名直接暴露给读者时全是**学术腔**：读者不是来检索的，是来被击中的。对照爆款范本（原版《高性价比人生指南》34 节名）：「不要早死」「不要浪费钱」「养孩子划不划算」「别把自己搭进去」——没有一个分类词，每个都在说读者自己的事。

## 二、四条命名范式（从人性钩子里来）

1. **损失厌恶**：人怕失去甚于想得到。「投资先学会不亏钱」「想创业，先看别人怎么死的」。
2. **划算框架**：把受益换算成账。「选择比努力值钱」「当老板前先算清这笔账」「身体是最不该透支的资产」。
3. **悬念反差**：制造认知缺口。「聪明人的脑子里装了什么」「为什么有人学什么都快」。
4. **场景直白**：一句话还原深夜搜索框。「心里难受的时候看什么」「养孩子不靠吼」。

配套规则：4–14 字；同类章句式必须有变化（不许全是「别再××」）；禁词=认知/方法论/自我管理/素养这类论文词。

## 三、desc 是标题的「下半句」，不是定义

15–32 字，接着标题的悬念说，给一个具体收益或画面（数字、书名、结果），不用「本篇讲述…」的说明腔。好例子：「吵赢一架、输掉一个人：亲密关系里的说话分寸」。数字口径必须用脚本从产物里数出来（每章卡片数），不许手写估数——首版 desc 把卡片数写成「本」，口径就错了。

## 四、生产流：人写 → 模型二审 → 人工终判

1. 人工按范式写 31 条草案（保留 id 键值不变，只改 name/desc——**键值与文案分离**，改文案不触碰归类数据与构建管线）。
2. 模型批判性二审（GLM，prompt 里带 rules+全部草案，要求逐条 keep/fix+狠批）：本轮 fix 7 条，命中「口号感弱」「拗口」「半学术腔」等真问题。
3. 人工终判采纳与否，并统一数字口径、去重复措辞（模型改写会引入新的口径错）。
4. 改 chapters.json → 跑 build_cards 重建 chapters.js → DOM stub 冒烟 → push → 轮询线上 chapters.js 确认新文案生效。

## 五、坑

- 模型二审不是橡皮图章也不是全信：7 条 fix 里 desc 有重复措辞（「越会说话」式回环）、数字口径跟着草案错——**终判必须回人工**。
- 标题改动只涉及 chapters.json 一个源文件，管线里 chapters.js/books.html/index.html 全部由它派生——单一事实源的好处此时最大。
