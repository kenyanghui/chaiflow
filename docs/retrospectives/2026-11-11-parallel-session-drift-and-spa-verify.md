# 2026-11-11 · 多会话并行改站漂移 + SPA 站点验收（十页扩十二页集成）

## 1. 门（GATE — 事件与影响）

- 发生了什么（事实，含时间线）：
  - 收口会话在已上线的课程站（React SPA，GitHub Pages + 自定义域名）上集成四块新内容：技能课程化改版、专家课程、产品实证页、工作坊页。本机先提交集成（页数 10→12、导航 11 项），lint/build/红线扫描三绿。
  - 提交后回读 `git log --stat` 发现：同一分支的 HEAD 已被另一并行会话的「整站换壳」提交顶替——站点品牌、导航、路由表全部换成另一条业务线的口径，本站原有六条路由被删，换壳页面与四块新产出混在同一棵树里。
  - owner 定夺回滚：从上一版站点基底恢复品牌/路由/导航/首页/关于页，删除换壳页面，四块内容产出全部保留并重新接线。
  - 集成收口时又暴露两处结构问题：① CI 门禁脚本在基底版本里已被删除，但 workflow 仍在引用它（存量悬空，push 即红）；② 四块产出中的工作坊页把另一业务线的「六场评审训练营」硬编码进页面，而仓内正确的四场数据文件存在却未被页面消费。
- 影响：当日两次 CI 红（悬空门禁脚本 1 次；部署前门禁失败 1 次）；一次线上页面主题错（线上 h1 与数据源标题不一致，页面 DOM 仅为壳级体积、特征词命中 0）；站点页数 10→12。
- 怎么发现的：① HEAD 主体与预期基线不符（提交信息与文件清单回读）；② 线上用无头浏览器 `--dump-dom` 渲染后按关键词断言，而不是只看 HTTP 状态码——正是这一步抓出「页面渲染了错主题」。

## 2. 成（SUCCESS — 哪些机制起了作用）

- 本地三绿门（lint / build / 红线扫描）在提交前拦掉了低质提交；线上验收坚持「渲染后断言」，把「HTTP 200 但内容错」这类问题挡在发布判定之外。
- 已建档的 SPA 深链档案（深链返回 404 状态 + 壳页面，属托管平台标准行为）被复用，没有把正常现象误判成整站故障。
- 产出与数据分离的结构让修复变成「接线」而不是「重写内容」：字段契约（空日期→排期中、不渲染报名按钮）使页面重写一次到位。
- 回滚策略收敛了损失：只恢复基底五件文件 + 删除换壳页，四块产出零返工。
- 缺口同样明确：本次无——缺少的是「多会话并行审计」「门禁脚本与 workflow 一致性」「页面标题溯源数据源」三条守则，全部进 ACTION。
