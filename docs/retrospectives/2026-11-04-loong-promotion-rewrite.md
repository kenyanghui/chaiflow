## 1. 翻译范式：内部视角 → 买方语言

改写最大的产出不是文案本身，是确认「翻译」这个动作有固定范式：

| 内部黑话（旧） | 买方语言（新） | 翻译规则 |
|---|---|---|
| N 条工程铁律 / 证据链验收 | 「不撒谎的技术团队」「做完的每一步都有证据」 | 机制数量不露，机制翻译成承诺 |
| Skill 与工作流开发流水线 | 「干得好的活沉淀成技能，下次一句话复用」 | 把「我们怎么造」改成「你得到什么」 |
| map/pipeline/race 满编扇出 | 分进合击 / 流水接力 | 调度术语过兵法/直白话 |

能力宣传三档诚实性：已上线才说有；灰度才说近期；没做不说。

## 2. 做对了的

- **两轮节奏**：第一轮重写定位与话术，第二轮按 owner 定调聚焦优势点——先翻译范式成型，再套用，第二轮速度远快于第一轮。
- **四步验证两轮全过**（双端渲染/链接复验/push 确认/live 回读），零 CSS/JS 变更路径反而零遗漏风险。

## 3. 踩过的坑

| 坑 | 对策 |
|---|---|
| 懒加载假破图：loading=lazy 图片在 headless 渲染时未进视口不加载，破图断言误报 | 断言前滚动到底触发加载，或对该类图改查 data-src 存在性 |
| 能力宣传超出实际（承诺了没上线的） | 三档诚实性硬规矩（见上） |
| 000 与 200 并存 | 出网受限环境先信本机回环（200=资源在），公网可达性另行抽测 |
| 版本号手抄落后一版 | 站上版本从机器可读源生成，不手抄 |

## 4. 流程经验

- **远端有新提交是常态**：push 被拒 `git pull --rebase` 重推即可；与 443 退避重试并列为 push 失败两类常见形态（已入 site-iteration-playbook 第六节）。
- **最低成本扩版=样式克隆**：新板块优先复用现有 section 的 DOM 模式与 CSS 类，零新增 CSS 即零遗漏风险；表达不了才新增，新增必同步 reveal 选择器。
