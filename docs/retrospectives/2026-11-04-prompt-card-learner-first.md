# 2026-11-04 · 指令卡三稿演进复盘——「以学习者为中心」就是替学习者把话想好，而不是教流程

## 1. 门（GATE — 事件与影响）

- 发生了什么（事实，含时间线）：wk1「WorkBuddy 提示词」区块一天内三稿，前两稿都被 owner 打回：
  - **v1（8236f867）想象聊天卡**：「①交素材→②出初稿（800 字口语化）→③进草稿箱」——流程纯属编造，真实产线是 ima 接入/公众号接入/装 rsi 技能（详见 [workshop01-card-authenticity.md](./2026-11-04-workshop01-card-authenticity.md)）。
  - **v2（owner 修正+会话沿用）真实配置卡但步骤腔**：内容对了（Client ID/API Key/AppID/AppSecret/rsi 技能仓），但写成了「配置公众号流水线，第一步接我的…」「第二步接我的…」「Client ID =（　）、API Key =（　）。请收好并验证连通，告诉我能读到哪些知识库」——先讲步骤、再讲条件、占位符+验证要求，一张卡七八行。
  - **v3（98776384）owner 三句定稿**：原话只有三句——「接ima知识库，API Key和Client ID是：」「接微信公众号，AppID和AppSecret是：」「安装github.com/kenyanghui/rsi-ima-workbuddy-wechatpub，跑一次工作流」。凭证由学习者自己贴在冒号后；不做第一步第二步；克隆面（guide 第 3 节）同次同步换稿。
- 影响：v2 虽内容真实，但把「配置怎么叙述」的复杂度转嫁给了学习者——学习者要先读懂卡片里的步骤说明、找到占位符、理解「验证连通」是什么意思，才敢发送。v3 学习者只做四件事：复制→贴进 WorkBuddy→把自己领的凭证贴在冒号后→发送。复杂度的归处：凭证怎么领（上方「开工前三件事」区块）与产线怎么跑（rsi 技能内部），不占指令本身一行。
- 怎么发现的：owner 两轮原话打回——v1 后「你专业一点」；v2 后「还是太复杂了，用户复制，贴到 workbuddy，再复制记下来的信息，发送，应该是这样，不要难过（漏字：要难搞）什么第一步第二步」。
