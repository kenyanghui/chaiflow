# D24 · 工作坊材料全量校对：基准对齐先于派发（2026-11-04）

> 编号史：内部 chai-workflow 仓同日决策编 D21；本仓截至昨日已用至 D23，按 guard 纪律本仓占 D24，两侧内容同源、编号各自独立。

## 背景

第二期工作坊（fork 讲师站主线）全套课件、学员材料、海报上线后，做了一轮**全量只读校对**：材料分包并行派给四个校对执行位（按材料分段：课件+海报 / 01–04 / 05–08 / 09–12），每份 prompt 附事实基准（红线信息、主线口径、模块数字、仓库与视频链接），产出四份「错误清单（文件+行号+原文+应为）+ 可疑项 + 通过项」结构化报告。

## 决策要点

1. **派发前基准必须对齐最新决策**：本轮最大教训——校对报告 A 把课件旧稿时长（50′/55′/40′）当基准，反向判学员材料（45′/45′/35′+第 0 节 20′，出自更早的定档决策）为错。汇聚裁决靠 `git log -S` 考古定谳：旧稿从未同步定档决策，**成文决策优先于任何单体文件**。此后派发的 prompt 内事实基准一律附决策出处编号。
2. **多源冲突的裁决顺序**：成文决策 > 与决策同波次提交的材料 > 单体文件现状 > 报告声称的"基准"。仲裁证据用 git 考古（`git log -S "关键词" -- 文件`）而非人工记忆。
3. **交付物编号纪律**：课堂交付物三件为主口径；底盘凭证归第 0 节自检项，不占交付编号——编号一旦在公开页出现，所有材料同号同义。
4. **A4 单页红线加内容的前置动作**：单页已满的卡片要加行，先想「并进哪个已有块」再想收紧样式（行高/内边距降一档），最后才是删内容——本轮加热身视频行先撑破到 2 页，行高 1.32→1.26 拉回单页。
5. **改标题=全链路改名**：对外标题改动须全链扫一遍——课程数据源、场地首页 hero、课件、海报、自助跟做手册、五步口径话术、README 场次表，grep 旧字串清零+新字串命中双验证。

## 落地与坑

- 四份报告共 18 处确认错误+11 处可疑；可疑项逐条回源裁决，不直接采信（"19 分钟"实为现场动手时间与节时长两个口径，非错）。
- 产物重生成后逐件验：A4 材料 pdfinfo 级页数验证、课件 PDF 页数与公开页声明一致（30→29）、海报长图重截图重裁剪。
- 线上验证用无头浏览器 dump-dom（SPA 用 curl 只拿到空壳）；旧口径字串全量 grep 归零、新字串计数命中；静态资产逐个 200。
- 坑：校对执行位产出的报告文件属主可能与登录用户不同，清理时需提权。

## 后续义务

- 同类全量校对的 prompt 模板固化：范围+基准（附决策编号）+输出格式（错误/可疑/通过三段）+只读约束。
- 时长/交付物/标题三类口径再改，以本仓对应决策为准；改后必须双仓双验证（源仓+站仓）。
