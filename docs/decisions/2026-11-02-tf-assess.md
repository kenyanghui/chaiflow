# D19：过级自评表 /tf-assess/ ——「对照评分表」的正确形态是可填写，不是陈列；兼反思为什么第一版没想到（2026-11-02）

## 背景
learning-path 页按官方 TF1-1~TF3-3 评分表重写为 33 个技能点后（D18 方向），站长指出：「了解 Level 几不重要」，要的是**在线自填的评测表**——用户对照技能点逐项自评，四个 Level 各一张表。技能点已就位，缺的是「表」本身。

## 实现（完全复用 workbook 引擎模式，零新增服务）
```
chai.aibay.asia/tf-assess/     静态页（vanilla JS，public/ 直出，无构建链）
  ├─ SPECS 内联（四 Level：TF1×8 / TF2×11 / TF3×14 / AI×5，与 src/data/learningPath.js 同源口径）
  └─ localStorage 键 tf_assess:{id}（tf_assess:meta 存姓名/目标），hash 切卡（/tf-assess/#tf2）
```
- 每项 **0/1/2 三档**（还没做到/部分做到/完全做到），radio 控件。
- **一票否决判定**：各级关键项（TF1 第 8 项指令、TF2 四项讲解技巧、TF3 第 1 项 why/what 拆页）必须=2，否则结果区直接判「⛔ 未达标」——这是官方评分表的核心规则，自评表必须带。
- 结果区四态：未开始 / 一票否决未达标 / <60% 尚需修炼 / ≥80% 且全评→「可约观察家实测」。
- 导出/复制 Markdown（含完成度与否决项提示），发给师父或存档；「清空本级」按 Level 独立。
- learning-path 四张卡 CTA 全部换为「在线自评 · TFx」入口（`了解 Level N`、`查看 S 级技能` 均移除——用户点名不重要）。
- 5cdfeca9 上线，/tf-assess/ 200，四入口在 bundle。

## 反思：为什么第一版（89f98b86）没想到做评测表？
1. **把「对照评分表」理解成了内容任务，而它本质是交互任务。** 我重写时把 33 个技能点当成要「展示正确」的静态文案；但评分表在现实里的形态就是「可勾选的表格」——表格天然是填写物。站长看到一页陈列的技能点，第一反应必然是「能不能填」。
2. **模式资产在眼前却没有按「能力」检索。** /workbook（fc556d51）上一轮刚上线，tab+localStorage+导出引擎就在同一个仓库的 public/ 里。我检索既有资产时按**页面名**（workbook=工作坊手册）归档，而不是按**能力**（「线上可填写表单」模式）归档，于是「自评表」需求出现时没有触发联想。教训：**资产清单应记能力，不记页面**。
3. **「表」类需求的判定口诀**：凡是表格/评分/清单/检查项，先问一句「这是展示物还是填写物？」填写物默认走 workbook 引擎形态（静态页 + localStorage + hash 切卡 + 导出 Markdown），成本≈一次数据填充（本次 SPECS 直接来自 learningPath.js，半小时上线）。
